## 1. Идея

Лёгкое Windows-приложение для смены визуального стиля курсора мыши. Пользователь
собирает/импортирует **пресеты** (наборы из ~16 файлов `.cur`/`.ani`, по одному
на каждую системную роль курсора) и переключается между ними кликом по ячейке
в галерее. Без детальной настройки (цвет, DPI, обводка и т.п.) — только
внешний вид, целиком пресетом, плюс один глобальный ползунок размера курсора
(системный, не per-роль).

Референс уже есть на диске: `C:\Users\Capitan Salat\Desktop\Plagins\Cursor`
— 16 файлов `.cur/.ani` с "говорящими" именами + `AquaCursor.zip` с тем же
набором внутри архива. Имена файлов один-в-один совпадают с ролями курсора
Windows — это и есть эталонная схема соответствия.

## 2. Платформа: Windows Desktop, .NET 8 + WPF (C#)

**Выбрано: .NET 8 / WPF, self-contained trimmed publish.**

Почему:
- Смена курсора в Windows — это чисто платформенный API
  (`SystemParametersInfo(SPI_SETCURSORS)` + ветка реестра
  `HKCU\Control Panel\Cursors`). Кроссплатформенность не нужна и не имеет
  смысла — задача жёстко привязана к Win32.
- WPF даёт нормальный drag-and-drop, биндинг для сетки ячеек-превью и
  собственный визуальный стиль без веб-обвязки — в отличие от Electron,
  который для "лёгкой программы" избыточен (сотни МБ, Chromium-рантайм).
- .NET 8 self-contained + trimming даёт разумный вес (десятки МБ, не сотни),
  один exe, не требует установки .NET у пользователя.
- P/Invoke из C# к `user32.dll`/реестру — тривиален, богатых сторонних
  библиотек не требуется для основной механики.
- `System.IO.Compression.ZipFile` — работа с .zip из коробки, без зависимостей.

Альтернативы и почему отклонены:
- **Electron/Tauri (веб-стек)** — Tauri в принципе жизнеспособен (лёгкий,
  Rust-бэкенд умеет WinAPI), но добавляет веб-слой ради UI, который в WPF
  строится проще и без второго языка. Electron — явно тяжелее заявленной цели.
- **Чистый Win32/C++** — минимальный вес, но кратно дольше в разработке
  (вручную писать drag&drop, рендер сетки, парсинг архивов). Не оправдано
  для утилиты такого масштаба.
- **WinUI 3** — современнее внешне, но капризнее в упаковке/зависимостях
  (Windows App SDK runtime) ради утилиты, которой не нужен Fluent-хром.

## 4. Хранилище данных

```
%LOCALAPPDATA%\CursorCustomizer\
  presets\
    <preset-id>\
      manifest.json      # {name, createdAt, roles: {Arrow: "normal.cur", ...}}
      files\*.cur/*.ani   # копии файлов, скопированные в кэш (не зависят от исходного архива/пути)
      thumbnail.png       # опционально, кэш превью
  state\
    active.json           # id текущего применённого пресета
    settings.json          # {cursorSize: 32..256}  — глобальный размер, не привязан к пресету
    previous-snapshot\     # снимок системных курсоров ДО последнего применения — для отката
```

Ключевой момент по пункту "кэшировать стили, чтобы восстанавливать данные":
при импорте файлы **копируются** в `presets\<id>\files`, оригинал (архив/папка
на рабочем столе) после этого не нужен — пресет живёт независимо и переживёт
удаление исходников.

## 5. Функциональность → модули

| Требование | Реализация |

размер.

## 6. UI-поток

1. **Главный экран** — сетка ячеек-пресетов (превью = отрендеренная стрелка
   Arrow пресета + название). Клик по ячейке → применение (реестр +
   `SPI_SETCURSORS`), подсветка активной.
   В шапке, всегда на виду (не внутри сетки, не требует прокрутки) —
   **кнопка "Сбросить к курсору по умолчанию"**. Это приоритет №1 по
   надёжности: работает в один клик, без выбора пресета, независимо от того,
   пуста ли галерея или повреждён ли кэш пресетов (см. раздел 7, пункт 5).
   Рядом — менее приоритетная кнопка "Отменить последнее изменение" (откат к
   `previous-snapshot`, т.е. на шаг назад, не обязательно к дефолту).
   Внизу/в шапке — один слайдер "Размер курсора" (диапазон как в системных
   настройках Windows, шаг = системным шагам 32→256), действует сразу на
   активный пресет, живое превью без модалок.
2. **Добавление пресета**:
   - Drag&drop `.cur`/`.ani`-файлов (по одному или пачкой, включая
     перетаскивание целой папки или архива `.zip`/`.rar`/`.7z`) на зону
     "+ Добавить" в сетке, или кнопка "Обзор...".
   - Файлы автосопоставляются с ролями по таблице из раздела 3 (по имени).
   - Открывается **редактор пресета**: 16 слотов-ролей, распознанные —
     заполнены превью, нераспознанные/отсутствующие — пустые. Можно
     перетащить файл на конкретный слот вручную, или заменить уже занятый.
   - "Сохранить" → копирование файлов в кэш, генерация `manifest.json`,
     появление новой ячейки в галерее.
3. **Редактирование существующего пресета** — тот же редактор, открывается
   по двойному клику/контекстному меню "Изменить".
4. **Удаление** — контекстное меню ячейки → "Удалить" → подтверждение →
   стирание из кэша. Если пресет был активен — Windows остаётся на нём, пока
   пользователь не выберет другой (или предложить авто-переключение на
   "по умолчанию").

## 7. Механика применения курсора (техническая часть)

1. Для каждой роли — если слот заполнен, `RegistrySetValue` под
   `HKCU\Control Panel\Cursors\<RoleName>` = путь к файлу в кэше пресета
   (абсолютный путь, файлы не двигаются после импорта — стабильный путь).
2. Если слот пуст — не трогать соответствующее реестровое значение (роль
   останется от предыдущего пресета/системной темы) **или** явно писать
   пустую строку, чтобы форсировать системный дефолт — решить на этапе
   реализации редактора (вероятно: пустая строка = системный дефолт, чтобы
   пресет был самодостаточным и предсказуемым).
3. `P/Invoke SystemParametersInfo(SPI_SETCURSORS, 0, IntPtr.Zero, SPIF_SENDCHANGE)`
   — применяет немедленно, без релогина.
4. Перед шагом 1 — сохранить текущие значения всех 17 веток реестра курсоров
   в `previous-snapshot\manifest.json` (просто значения путей, без копирования
   файлов — они и так уже либо системные, либо лежат в другом пресете кэша).
5. Размер: значение слайдера пишется в `HKCU\Control Panel\Cursors\CursorBaseSize`
   (тот же ключ, что использует системная настройка "Ease of Access → Мышь" в
   Windows 10/11, диапазон 32–256) и применяется тем же `SPI_SETCURSORS`.
   Хранится глобально в `settings.json`, не в манифесте пресета — переключение
   пресета не сбрасывает выбранный размер.
6. Автозапуск/трей — **не нужен**. Запись в `HKCU\Control Panel\Cursors`
   персистентна сама по себе: Windows читает эту ветку реестра при каждом
   входе в систему и применяет её без участия стороннего процесса. Один раз
   применённый пресет переживает перезагрузку/релогин без того, чтобы
   приложение работало в фоне или стартовало с системой.
7. **Сброс к дефолту (кнопка №1)** — не полагаемся на собственный кэш/снапшот,
   чтобы кнопка работала даже при первом запуске или битых данных приложения.
   Windows сама хранит встроенную схему в
   `HKCU\Control Panel\Cursors\Schemes\"Windows Default"` — строка из 17
   путей к системным файлам курсоров (`%SystemRoot%\cursors\...`) в
   фиксированном порядке ролей. Кнопка читает эту строку, раскладывает её по
   тем же 17 веткам `HKCU\Control Panel\Cursors\<Role>`, обнуляет
   `CursorBaseSize` (сброс на 32 — системный дефолт), вызывает
   `SPI_SETCURSORS`. Если по какой-то причине схемы "Windows Default" нет в
   реестре (нестандартная система) — фолбэк: явные пути к
   `%SystemRoot%\cursors\aero_*.cur` зашиты в приложении как константа.

## 9. Дистрибуция: портативный exe (решено)

Без инсталлятора. Причины:
- Все изменения приложения — только в `HKCU` (реестр текущего пользователя) и
  `%LOCALAPPDATA%`, административные права не нужны, ставить в
  `Program Files` незачем.
- Автозапуск не нужен (раздел 7, пункт 6) — значит, инсталлятору как таковому
  нечего регистрировать (ни службы, ни записи автозагрузки, ни файловых
  ассоциаций на старте).
- .NET 8 self-contained single-file публикация даёт один `.exe` — скачал,
  запустил, данные пишутся в `%LOCALAPPDATA%\CursorCustomizer`. Удаление —
  просто стереть exe и (по желанию) папку с кэшем.
- MSIX/Setup можно рассмотреть позже, если понадобится авто-обновление —
  не блокирует MVP.

## 10. Тема оформления приложения — реализовано (v1.1.0)

MVP вышел только с тёмной темой (как и планировалось), светлая добавлена в
v1.1.0 раньше, чем предполагал бэклог. Фактическая реализация:
- `Themes/Dark.xaml` и `Themes/Light.xaml` — зеркальные `ResourceDictionary`
  с одинаковыми ключами (`Color.*`, `Brush.*`, `Style.*`), поэтому весь XAML
  резолвится одинаково независимо от активной темы.
- `ThemeManager` (Services): при первом запуске читает системную тему
  Windows (`HKCU\...\Personalize\AppsUseLightTheme`), сохраняет выбор в
  `settings.json` — дальше системные изменения темы не отслеживаются, только
  явный тумблер в шапке.
- Тумблер меняет активный `ResourceDictionary` в `App.Resources`, но так как
  вся вёрстка использует `StaticResource` (резолвится один раз при загрузке,
  не обновляется на лету), переключение темы пересоздаёт `MainWindow`
  целиком — с переносом позиции/размера/состояния окна, чтобы не было
  прыжка в дефолтную позицию экрана.

### 11.2 Локализация (поддержка языка) — ✅ готово

- `LocalizationManager` (Services) — по аналогии с `ThemeManager`: при первом
  запуске определяет язык по системной локали Windows
  (`CultureInfo.InstalledUICulture`), дальше — только явный выбор
  пользователя, запомненный в `settings.json`.
- Переключатель — кнопка в шапке рядом с тумблером темы, открывает список
  доступных языков.
- В отличие от темы (см. раздел 10), окно **не пересоздаётся** — весь текст

  `ReloadGallery()`, без визуального моргания окна.

### 11.3 "Свой пресет" — экспериментальный конструктор из существующих стилей

> Детальная проработка перед реализацией (модель данных, хранилище,
> UI-поток, точки интеграции с кодом, крайние случаи, план по шагам):
> `docs/features/custom-preset-builder/spec.md`.

Идея: не заставлять пользователя подбирать/рисовать новый файл под каждую
роль, если он хочет курсор-микс — а позволить **собрать пресет из ролей уже
импортированных пресетов**, без создания новых картинок.

- Это специальный контейнер, всегда присутствующий в галерее рядом с
  ячейкой "Windows по умолчанию" (не обычный импортированный пресет — не
  создаётся через drag&drop файла, а через свой конструктор).
- Клик по контейнеру открывает **свою мини-галерею** — список сохранённых
  сборок пользователя ("Свой пресет" может содержать несколько сборок, не
  одну, каждая переключаема независимо, как обычный пресет) + "+ Новая
  сборка".
- Редактор сборки переиспользует UI из раздела 6 (16 слотов-ролей), но
  источник для слота — не только файл с диска: в первую очередь **выбор из
  ролей уже существующих пресетов** (мини-сетка превью: как эта конкретная
  роль выглядит в каждом импортированном пресете → клик подставляет её).
  Слот поддерживает оба источника — можно часть ролей взять из пресетов,
  часть — подгрузить файлом отдельно, как в обычном редакторе.
- **Файлы не дублируются.** Манифест сборки хранит не копии, а ссылки
  `{role: {presetId, fileName}}` на файлы в кэше исходных пресетов (раздел
  4). Итоговый набор путей для реестра собирается на лету в момент apply —
  для системы (`SPI_SETCURSORS`) сборка неотличима от обычного пресета,
  разница только в том, как её редактор хранит источники.
- **Обработка удаления исходника**: если пресет, чья роль использована в
  сборке, удалён — соответствующий слот в сборке помечается как "битый"
  (broken reference). При apply такой сборки — предупреждение с списком
  недоступных ролей, откат этих ролей на дефолт до переназначения вручную
  (сама сборка не удаляется и не ломается целиком из-за одной пропавшей
  роли).

### 11.4 Реакция курсора на удержание кнопки мыши (custom trigger-роли) — идея, не начата

Идея: пользователь хочет, чтобы при удержании определённой кнопки мыши (например,
ЛКМ) показывался свой кастомный курсор — роль, которой нет среди системных ролей
Windows (раздел 3), потому что Windows не отслеживает состояние кнопок мыши для
смены курсора вообще.

- Механизм принципиально другой, чем весь остальной проект: не запись в
  `HKCU\Control Panel\Cursors` (раздел 7) — эта ветка реестра статична и не
  реагирует на события ввода, только на системный контекст (текст, ссылка,
  занятость и т.п.), который определяет сама ОС.
- Нужен фоновый low-level мышиный хук (`SetWindowsHookEx(WH_MOUSE_LL)`),
  отслеживающий `WM_LBUTTONDOWN`/`WM_LBUTTONUP` (и аналогично для других
  кнопок), который на нажатии подменяет текущий системный курсор через
  `SetSystemCursor` на кастомный файл, а на отпускании — восстанавливает
  оригинал.
- Из этого следует прямое противоречие разделу 7 п.6 ("автозапуск/трей не
  нужен") — эта фича **требует** постоянно работающего фонового процесса
  (как минимум в трее), пока активна хотя бы одна custom trigger-роль:
  реестровый механизм переживает релогин сам по себе, хук — нет.
- Технические нюансы на будущее: `SetSystemCursor` "забирает" переданный
  хендл курсора, поэтому нужен `CopyIcon` перед каждым вызовом; после
  завершения работы приложения нужно вернуть системе исходные курсоры
  (`SystemParametersInfo(SPI_SETCURSORS)` восстановит из реестра).
- UI-концепция (черновая, требует проработки): новая секция в редакторе
  пресета — "доп. роли по событиям мыши" (нажатие ЛКМ/ПКМ/СКМ, возможно
  double-click) — отдельно от 16 стандартных ролей-слотов, т.к. живут в
  другом хранилище/механизме применения.

### 11.5 Экспорт/импорт пресетов — поделиться с другим человеком

Идея: обратный сценарий к архивному импорту (раздел 0) — не только *принимать*
чужие наборы курсоров, но и *отдавать* свои, чтобы другой человек мог получить
готовый, уже настроенный пресет (включая точки опоры, см. раздел «Редактор
точки опоры»), а не пересобирать его вручную из россыпи файлов.

- **Экспорт по выбору.** В контекстном меню ячейки пресета (там же, где
  "Изменить"/"Удалить") — пункт "Экспортировать". Открывает отдельное окно
  выбора: список всех пресетов с чекбоксами (можно выбрать один или
  несколько за раз), кнопка "Сохранить как .zip". Упаковывает файлы ролей
  выбранных пресетов + `manifest.json` (имя, размер, хотспоты) в архив,
  который пользователь сохраняет через стандартный диалог сохранения файла.
- **Импорт — переиспользует существующий пайплайн.** Полученный `.zip`
  ничем не отличается для системы импорта от стороннего архива с курсорами
  (раздел 0, `ArchiveImportService`) — тот же путь: drag&drop на главное
  окно или в зону "Обзор" редактора. Разница только в том, что "родной"
  архив содержит `manifest.json`, поэтому при его обнаружении внутри
  распакованной папки импорт может пропустить шаг автораспознавания ролей по
  имени файла и подставить точное сопоставление роль → файл из манифеста
  напрямую, включая уже сохранённые хотспоты и размер курсора — то есть
  копия пресета получается идентичной оригиналу, а не восстановленной по
  эвристике имён.
- **Открытие в отдельном окне после переноса в приложение** (как просил
  пользователь) — если распознан "родной" `manifest.json`, вместо обычного
  редактора с автозаполненными слотами можно сразу показывать окно
  предпросмотра импортируемого пресета (имя, превью всех ролей, размер) с
  кнопками "Добавить в галерею"/"Отмена" — чтобы получатель видел, что именно
  он копирует, прежде чем сохранить.
